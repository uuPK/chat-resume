# OfferMaster PPT 技术优势

这份文档用于制作项目展示 PPT，可直接拆成 slides。

## 1. 宏观技术优势：校企生协同闭环

OfferMaster 不是单一 AI 工具，而是把学生、企业、学校三方放进同一个就业能力闭环：

```text
学生简历 -> 岗位/JD 匹配 -> 简历优化 Agent -> 企业投递
       -> 模拟面试 Agent -> 面试报告 -> 学习路径/学校课程 -> 再优化
```

PPT 表达重点：

- 学生侧：简历优化、岗位匹配、模拟面试、学习路径。
- 企业侧：岗位发布、投递管理、候选人匹配分析。
- 学校侧：市场技能缺口分析、AI 课程生成、课程发布。
- 系统价值：把“就业准备”从一次性建议变成可持续反馈循环。

## 2. 多 Agent 联动优势

系统中的 Agent 不是孤立聊天机器人，而是围绕业务状态协作：

- 简历优化 Agent 负责把岗位目标转成可确认的简历修改。
- 面试 Agent 负责用面试验证简历中的经历和能力。
- 报告 Agent 负责把面试表现转成结构化复盘。
- 学习路径 Agent 负责把短板转成 4 周成长计划。
- 学校课程生成能力负责把市场缺口转成课程供给。

PPT 亮点话术：

> 系统通过多个 Agent 串联学生就业过程，让每一次简历修改、面试反馈和学习计划都能回到同一个成长闭环里。

## 3. 简历优化 Agent 技术优势

### 3.1 不是生成建议，而是真实修改结构化数据

简历 Agent 不只输出“建议你这样改”，而是通过工具调用修改简历 JSON。

核心工具包括：

- `update_summary`
- `update_profile`
- `update_item_fields`
- `update_bullet`
- `add_bullet`
- `remove_bullet`
- `update_skills`
- `upsert_job_application`
- `generate_job_match_summary`

PPT 亮点：

- LLM 负责判断和生成修改意图。
- 工具层负责结构化写入。
- 数据库保存最终简历状态。
- 前端实时刷新简历预览。

### 3.2 Human-in-the-loop：用户确认后才落地修改

简历修改采用“预览 diff -> 用户确认 -> 真正写入”的机制。

流程：

```text
Agent 生成工具调用
-> 后端在副本上预执行
-> 生成 diff 预览
-> 前端展示确认卡片
-> 用户接受或拒绝
-> 接受后写入真实简历
```

PPT 亮点：

- 降低 AI 自动修改风险。
- 用户始终掌握最终控制权。
- 适合简历这种高敏感个人材料。

### 3.3 可控工具边界，降低幻觉风险

简历 Agent 有明确安全边界：

- 不能编造经历、数字、奖项和年限。
- 只能修改当前用户拥有的简历。
- 只能修改当前可见模块。
- item id、bullet id 必须来自当前简历 JSON。
- 工具层有 section 校验和字段白名单。

PPT 亮点话术：

> 简历优化不是让大模型自由发挥，而是让大模型在受控工具边界内完成可审计修改。

### 3.4 SSE 实时流式交互

简历 Agent 通过 SSE 把过程事件推给前端。

典型事件：

- `session_started`
- `text_delta`
- `tool_call`
- `tool_pending`
- `tool_confirmed`
- `tool_rejected`
- `tool_result`
- `done`

PPT 亮点：

- 用户能看到 Agent 正在思考、调用工具、等待确认和完成修改。
- 支持流式内容显示，交互体验更接近真实协作。
- 事件持久化后支持断线回放。

### 3.5 Session 持久化和恢复

系统保存 Agent session、stream events、tool preview 和 confirmation event。

价值：

- SSE 断线后可用 Last-Event-ID 回放。
- 用户确认工具时即使原连接中断，也能恢复 session。
- 方便排查 Agent 行为和工具调用链路。

## 4. 面试 Agent 技术优势

### 4.1 实时语音模拟面试

面试系统支持实时语音交互：

- WebSocket 连接实时语音会话。
- 处理候选人语音输入。
- 播放面试官语音输出。
- 保存面试官问题和候选人回答。

PPT 亮点：

- 比文本问答更接近真实面试压力。
- 面试过程可以沉淀为可复盘数据。
- 后续报告和学习路径都有真实问答证据。

### 4.2 结构化面试 Session

面试不是一次普通聊天，而是有结构化状态：

- 目标岗位
- 目标公司
- JD
- 面试类型
- 难度
- 面试计划
- 问题轮次
- 候选人回答
- 面试报告

PPT 亮点：

> 每一场面试都被保存成可追踪、可复盘、可再次训练的数据资产。

### 4.3 面试报告生成

面试结束后，系统根据真实问答生成结构化报告。

报告内容包括：

- 总体结论
- 岗位匹配判断
- 优势
- 短板
- 面试官风险点
- 逐题点评
- 推荐回答
- 学习建议
- 简历反馈

PPT 亮点：

- 不只是“打分”，而是给出可行动的改进建议。
- 逐题复盘能明确指出问题发生在哪里。
- 报告能继续触发学习路径生成。

### 4.4 LangGraph 多专家面试架构

项目中已有 LangGraph 多专家面试原型。

节点设计：

- `Evaluator`：后台裁判，对候选人上一轮回答评分，更新能力矩阵。
- `Supervisor`：面试主管，决定下一步交给哪个专家。
- `Tech_Expert`：技术考官，负责项目深挖和基础知识考察。
- `HR_Expert`：行为面试官，负责 STAR、协作、抗压和职业规划。
- `ToolNode`：工具节点，连接题库 RAG 和简历知识图谱。

PPT 亮点话术：

> 面试 Agent 不是单模型连续提问，而是由主管、技术专家、HR 专家和后台裁判共同协作的状态图。

### 4.5 题库 RAG 支撑专业提问

面试技术题库以 JSONL 形式存储，导入 pgvector 后支持语义检索。

题库内容包括：

- 技能标签
- 难度
- 题目
- expected points
- followups
- rubric

PPT 亮点：

- 技术问题有题库依据。
- 能根据候选人技能栈检索相关问题。
- 支持追问点和评分标准，减少随机提问。

## 5. 工程架构优势

### 5.1 分层清晰

后端分层：

- HTTP entrypoints：处理接口和鉴权。
- services：处理业务流程。
- agents：处理 Agent runtime 和图编排。
- tools：处理可执行工具。
- models/schemas：处理数据模型。

优势：

- 业务逻辑、Agent 编排和工具执行边界清晰。
- 后续可以独立替换模型、工具或前端交互。

### 5.2 可观测性

系统已有多类日志和 trace：

- 请求日志
- 慢请求日志
- DB 查询统计
- Agent trace
- 工具调用 trace
- SSE 阶段耗时
- 报告生成阶段日志

PPT 亮点：

> Agent 系统不是黑盒运行，而是能追踪请求、模型、工具、确认和落库全过程。

### 5.3 事件驱动体验

简历优化和报告生成都使用流式事件：

- 简历优化：SSE 传输 Agent 事件。
- 报告生成：SSE 传输生成阶段和进度。
- 语音面试：WebSocket 传输实时语音和文本。

优势：

- 长任务不阻塞用户。
- 前端能展示真实进度。
- 更适合 Agent 的多步骤执行过程。

## 6. 数据闭环优势

系统会把每一步结果沉淀为后续输入：

- 简历内容影响岗位匹配和面试问题。
- JD 影响简历优化方向和面试目标。
- 面试问答影响报告。
- 报告影响学习路径。
- 学校课程影响学生学习计划。
- 学习后可以重新面试和优化简历。

PPT 亮点话术：

> OfferMaster 的关键不是“调用了一次大模型”，而是让每次 AI 交互都留下结构化结果，并进入下一轮决策。

## 7. 可直接放进 PPT 的亮点总结

- 校企生三方协同：学生成长、企业招聘、学校课程形成闭环。
- 多 Agent 联动：简历优化、模拟面试、报告复盘、学习路径相互衔接。
- 可控写入：简历 Agent 通过工具真实修改结构化简历，而不是只给建议。
- 用户确认：所有关键简历修改先展示 diff，确认后才落库。
- 反幻觉边界：工具层校验字段、模块、id 和权限，降低编造风险。
- 实时交互：SSE 和 WebSocket 支持流式 Agent、实时语音和进度展示。
- 多专家面试：Supervisor、技术专家、HR 专家和 Evaluator 组成 LangGraph 状态图。
- RAG 题库：pgvector 检索技术题、追问点和评分标准，支撑专业面试。
- 结构化报告：面试结束后生成岗位匹配、逐题点评、推荐回答和学习建议。
- 成长闭环：面试短板能转成学习路径，学习后可再次优化和面试验证。
